# Navigation integrity

Flow: `.agents/skills/verify-true-count/flows/links.mjs`. Unit test: `src/ui/routes.test.ts`.

Typed routes are off (ADR-0006), so every `href` is a plain string and a link to a screen that
does not exist compiles fine and ships as a 404. Two checks stop that:

- **`links` flow (e2e)**: reads every route from the build's own sitemap (`/_sitemap`,
  generated by expo-router from `app/`), loads each one at 1440 and 390 wide (plus the
  `?demo=1` sample views of `/lobby` and `/progress`), collects every in-app anchor (the nav,
  lobby and landing game cards, strategy cards, live-table links, the footer, …) and opens each
  target. It fails on an HTTP 404, a path that is not in the sitemap, or expo-router's
  "Unmatched Route" screen, and proves that last check can fail by opening an unknown path.
- **`routes.test.ts` (unit)**: every in-app path literal in `src/` and `app/` (quoted or the
  start of a template string, e.g. `` `/play?strategy=${id}` ``) must have a route file in
  `app/`. This covers targets no anchor shows, such as buttons that call `router.push`.

`no-hydration-errors` uses the same sitemap discovery (`scripts/routes.mjs`), so new screens
are covered by both without editing a list.
